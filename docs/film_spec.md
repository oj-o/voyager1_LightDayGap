## 1. 작품의 구조와 감각

### 1.1 세 가지 경험을 연결한다

1. **이동한 경로:** 1977년의 출발에서 목성·토성을 지나 황도면 위쪽으로 멀어진 실제 경로.
2. **도착하는 세계:** 보이저 위치에서 바라보는, 광행시간만큼 과거의 지구.
3. **지속되는 몸:** 꺼진 카메라 대신 남은 관측 장치와 방사성 동위원소의 열로 유지되는 탐사선.

탐사선에 의식이 있다고 주장하지 않는다. ‘경험’은 **위치·수신·측정·전력 상태를 관객의 시청각 경험으로 번역한 것**이다.

### 1.2 연출 원칙

- 거대한 우주 전경에서 시작해 작은 점, 긴 기다림, 미세한 변화로 수렴한다.
- 항성은 거의 정지해 보인다. 광속 비행 터널이나 지나가는 별무리를 기본 효과로 쓰지 않는다.
- 보이저를 따라가는 외부 카메라와 보이저 위치의 가상 카메라를 구분한다.
- 화면을 읽게 하는 시간과 아무 일도 일어나지 않는 시간을 확보한다.
- 궤적·전파·자기장 선은 실제 우주에서 눈에 보이는 물체가 아니라 이해를 위한 표시다.
- 주요 감정은 장엄함, 거리감, 기다림, 지속성이다. 해설은 짧고 담담하게 낭독한다.

## 2. 실제 경로: 어떤 사실을 어떤 데이터로 보여줄 것인가

### 2.1 역사적 뼈대

| 시점 | 사건 | 영상에서의 의미 |
|---|---|---|
| 1977-09-05 | 지구에서 발사 | 출발점과 인간의 시간 |
| 1979-03-05 | 목성 최근접 통과 | 중력 도움으로 휘는 경로 |
| 1980-11-12 | 토성 최근접 통과, 타이탄 탐사와 연결된 경로 | 이후 황도면 북쪽으로 향하는 방향 변화 |
| 1990-02-14 | ‘창백한 푸른 점’ 촬영 | 역사적으로 실제 이루어진 뒤돌아보기 |
| 2012-08-25 | 태양권계면을 넘어 성간 환경에 진입 | 눈에 보이는 벽이 없는 경계 |
| 2026-11-18 예상 | 지구로부터 1광일 | 정보가 도달하는 데 걸리는 시간의 규모 |

임무 연혁과 방향은 NASA의 설명을 따른다.[S02][S03][S04] 목성·토성 통과를 천왕성·해왕성 근접 탐사로 연결하면 안 된다. 그 후속 근접 탐사는 보이저 2호의 경로다.

토성 이후 황도면 북쪽 약 35°라는 설명은 개괄적인 방향이다. 모든 좌표에 35°를 강제로 부여하지 않는다. 3차원 궤도의 방향·곡률은 취득한 벡터가 결정한다.

### 2.2 ‘실제 경로’의 구현 의미

실제 경로는 사건 여섯 개를 임의의 곡선으로 연결한 선이 아니다. 날짜별 위치·속도 벡터를 사용한다. 과거 구간도 모든 순간을 직접 촬영한 자료가 아니라 추적·항법 자료를 반영한 재구성일 수 있다. 미래 구간은 예측이다.[S05][S06]

- JPL Horizons 또는 적절한 JPL/NAIF SPICE 커널을 사용한다.
- 보이저 1호: `-31`, 지구 중심: `399`, 태양: `10`, 목성: `599`, 토성: `699`, 타이탄: `606`.[S07]
- 과학 계산에는 공통 원점인 태양계 질량중심, 공통 좌표축, 공통 시간척도를 사용한다.
- 원자료를 보존하고 시각화용 데이터를 별도로 만든다.
- 데이터를 가져오지 못한 구간은 생략하거나 ‘개념도’로 표시한다. 실제 경로라는 표기를 유지한 채 직선을 채워 넣지 않는다.

### 2.3 권장 표본 간격

| 구간 | 시작 권장 간격 | 보완 |
|---|---:|---|
| 수십 년 전체 경로 | 7일 | 작은 화면에서의 경로 오차를 확인 |
| 목성·토성 통과 전후 | 5~30분 | 전후 약 10일을 별도로 고밀도 취득 |
| 1광일 사건 주변 | 1시간 | 24시간 변화량과 광행시간 계산 |
| 사건 시각 재계산 | 보간 후 근 찾기 | 더 촘촘한 자료로 수렴 확인 |
| 발사 직후 | 제공 범위에 따라 설정 | 자료 시작 이전을 임의 외삽하지 않음 |

중력 도움은 행성 기준 접근·이탈 방향이 달라지고, 태양 기준 속도와 에너지가 달라지는 과정이다. 행성 가까이에서 경로가 직각으로 꺾이거나 엔진 불꽃으로 급가속하는 장면을 만들지 않는다.

### 2.4 태양권계면을 표현하는 법

태양권을 벗어난 것과 태양 중력의 영향이 끝난 것은 다르다. 오르트 구름 규모까지 포함한 태양계의 경계와도 구분해야 한다.[S03]

희미한 반투명 면이나 입자 통계의 변화를 사용할 수 있다. 이 면은 ‘영역 구분을 위한 개념 표시’이며, 실제로 발광하는 껍질이 아니다. 2012년의 통과가 2026년의 하루 동안 다시 일어나는 것처럼 편집하지 않는다.

## 3. 보이저가 지구를 바라보는 장면

### 3.1 실제 촬영과 가상 시점

실제 보이저 1호 카메라는 1990년의 마지막 촬영 뒤 꺼졌다.[S01][S04] 따라서 2026년의 장면은 다음처럼 표시한다.

> 보이저 1호 위치에서 계산한 가상 시점  
> 광행시간 반영 / 실제 카메라 영상 아님

역사적 ‘창백한 푸른 점’을 사용하면 `1990-02-14 / NASA/JPL-Caltech`를 표시한다. 그 사진을 2026년의 실시간 수신 영상으로 쓰지 않는다. 원래 사진의 광선 같은 무늬는 광학계의 산란 효과와 관련되므로, 우주에 고정된 빛의 띠로 이어 그리지 않는다.[S04]

### 3.2 시점 세 가지

| 모드 | 카메라 | 용도 |
|---|---|---|
| 외부 동행 시점 | 보이저 주변의 가상 위치 | 탐사선과 지구 방향을 함께 보여줌 |
| 보이저 위치 시점 | 계산상 보이저 위치에서 지구 방향을 봄 | 작고 멀어진 지구 |
| 계측 시점 | 시각 카메라 대신 관측량을 화면으로 구성 | 자기장·플라스마파·전력의 지속 |

고이득 안테나의 지구 지향을 시각 모티프로 활용할 수 있다. 다만 실제 자세·롤·장치 배치까지 재현하려면 자세 자료와 기체 자료가 필요하다. 위치 벡터만으로 기체의 완전한 자세를 알 수는 없다. 가상 카메라가 뒤를 본다고 탐사선 전체를 180° 회전시키지 않는다.

### 3.3 지구는 얼마나 작게 보이는가

지구 평균 반지름을 `6,371 km`, 거리를 정확히 1광일로 둔 단순 계산:

\[
\theta_E = 2\arctan(R_E/D) \approx 0.1015\ {\rm arcsec}
\]

이것은 원반의 각지름이다. 넓은 화각의 4K 영상에서는 지구 원반이 한 픽셀보다 훨씬 작다. 대륙과 사람을 직접 보여주는 화면은 물리적 원경이 될 수 없다.

- 원경의 지구: 점광원과 위치 표시자.
- 확대 지구: 별도의 인셋으로 분리하고 ‘크기 확대·참조 이미지’ 표기.
- 사람·도시·기억의 이미지: 관객을 위한 연상 장면으로 분리.
- 점의 크기·밝기·검출 가능성: 서로 다른 값으로 취급한다. 각지름만으로 보이는지 판정하지 않는다.

같은 정도의 태양 거리라면 태양의 각지름은 약 11초각이다. 태양이 작게 보인다고 어두운 점으로 자동 처리해서는 안 된다. 노출과 눈부심을 함께 고려한다.

먼 거리에서 태양과 지구의 겉보기 분리각은 최대 약 `1 AU / D ≈ 0.33°` 규모다. 실제 값과 지구 위상은 해당 시각의 좌표로 계산한다. 화면 양 끝에 태양과 지구를 크게 떼어 놓으면 ‘각도 확대’ 표기가 필요하다.

### 3.4 지구의 ‘현재’와 ‘보이는 과거’

보이저의 수신 시각을 `t_r`, 지구의 빛 출발 시각을 `t_e`라고 하면 다음 식을 푼다.

\[
t_r-t_e
=\frac{\left|\mathbf r_V(t_r)-\mathbf r_E(t_e)\right|}{c}
\]

`r_E(t_r)`를 지구의 보이는 위치로 쓰면 광행시간을 무시한 것이다. 시각 비교 화면에서는 두 위치를 함께 그릴 수 있지만 다음처럼 이름을 붙인다.

- 실선: **수신되는 지구의 과거 위치**
- 점선: **선택한 좌표계의 같은 시각 지구 위치**

두 번째는 보이저가 동시에 관측하는 추가 지구가 아니다. 교육용 계산 표시다.

지구의 자전·구름·참조 영상도 `t_e`를 기준으로 배치한다. 24시간 전 모습이라고 지구를 180° 돌리지 않는다. 지구는 하루 동안 거의 한 바퀴 자전한다. 정밀한 확대 지구가 필요하면 지구 자세·시간 변환을 별도로 계산하고, 단순 24시간 자전은 근사라고 표시한다.

## 4. 1광일과 하루 동안의 변화

### 4.1 서로 다른 세 표현

| 표현 | 정확한 뜻 |
|---|---|
| 1광일 | 빛이 진공에서 86,400초 동안 이동하는 거리 |
| 1광일 거리에서의 하루 | 그 거리 부근에서 탐사선과 지구가 각각 24시간 동안 변화하는 상황 |
| 보이저가 1광일을 더 이동하는 시간 | 보이저의 속도로 그 거리를 추가 이동하는 데 필요한 시간 |

\[
c=299\,792.458\ {\rm km/s}
\]

\[
1\ {\rm light\!-\!day}=c\times86\,400
=25\,902\,068\,371.2\ {\rm km}
\approx173.1446\ {\rm AU}
\]

진공 광속과 AU를 사용한 단위 환산이다.[S13][S18] 한국어로는 약 **259억 km**다. 25.9억 km로 잘못 쓰지 않도록 한다.

### 4.2 화면 설계에 사용할 규모 비교

다음은 현재 정밀 항법값이 아니라, `v_V=17 km/s`, `v_E=29.78 km/s`를 둔 설명용 예시다.

| 물리량 | 예시 값 | 조건·해석 |
|---|---:|---|
| 빛의 하루 이동거리 | 약 259억 km | 진공에서 정확한 광속 사용 |
| 보이저의 하루 이동거리 | 약 146만 8,800 km | 17 km/s 일정 속도 |
| 보이저의 하루 이동거리 | 약 0.00982 AU | 위와 같은 조건 |
| 지구의 하루 공전 경로 길이 | 약 257만 3,000 km | 평균적 공전 속도 예시 |
| 보이저 속력 / 광속 | 약 0.00567% | 고속이지만 상대론적 고속은 아님 |
| 하루 이동거리 / 1광일 | 약 0.00567% | 전체 화면에서는 거의 움직이지 않음 |
| 같은 속도로 1광일 추가 이동 | 약 48.3년 | 등속 가정, 실제 임무 경과와 동일하지 않음 |
| 거리 증가에 따른 지연 증가 | 약 4.90초/일 | 지구를 고정하고 시선방향으로 17 km/s 후퇴할 때 |

지구의 공전 때문에 **태양에서 멀어져도 지구와의 거리는 어떤 기간에 줄어들 수 있다.**[S03] 영상의 지구–보이저 거리 카운터를 항상 증가하도록 고정하면 안 된다.

### 4.3 실제 변화율

같은 좌표 시각의 상대 벡터를 사용한다.

\[
\mathbf R=\mathbf r_V-\mathbf r_E,\quad
D=|\mathbf R|,\quad
\dot D=\frac{\mathbf R}{D}\cdot(\mathbf v_V-\mathbf v_E)
\]

\[
\frac{d(D/c)}{dt}=\frac{\dot D}{c}
\]

지구까지의 거리 변화에는 보이저의 전체 속력이 아니라 **상대속도의 시선방향 성분**이 들어간다. `4.90초/일`을 모든 날짜에 적용하지 않는다.

### 4.4 거의 변하지 않는 것을 보여주는 방법

S05의 40초를 실제 24시간에 대응시키면 `1초 영상=2,160초=36분`이다.

- 전체 지도: 실제 이동량 유지. 거의 정지해 있어도 정상이다.
- 옆의 국소 확대창: 시작 위치에서의 변위를 확대.
- 지구와 보이저 이동 비교: 동일한 km 눈금 사용.
- 화면 표기: `24시간 경과 / 변위 ×10,000`처럼 실제 적용 배율을 표시.
- 모든 확대는 렌더링 단계에서만 수행한다. 확대 좌표로 물리량을 다시 계산하지 않는다.
- 실제 별자리 방향을 주장하려면 항성 목록·기준 시각·시차를 사용한다. 임의 별 입자는 ‘배경 표현’으로 둔다.

### 4.5 밝기와 열의 하루 변화

일정한 방사 패턴·출력 조건에서 수신 세기에는 거리의 역제곱이 작용한다.

\[
F\propto D^{-2},\qquad
\frac{\Delta F}{F}\approx-2\frac{\Delta D}{D}
\]

1광일 거리에서 17 km/s로 순수하게 멀어지는 단순 예시에서는 하루에 약 **0.0113% 감소**다. 안테나 지향·송신 출력·수신기·위상에 따른 변화는 별도다. 이 감소량을 화면 전체의 급격한 소등으로 표현하지 않는다.

태양 복사 조도는 `r_S`를 태양까지의 거리로 써야 한다.

\[
F_\odot(r_S)\approx1361\left(\frac{1\ {\rm AU}}{r_S}\right)^2
\ {\rm W/m^2}
\]

`r_S≈173.14 AU`라는 예시에서는 약 `0.0454 W/m²`다. 이것을 우주 공간의 온도나 탐사선 부품 온도로 바꾸어 말할 수 없다. 온도는 내부 발열·복사·재료·차폐 등으로 결정된다.

## 5. 통신 지연·상대성·양자역학을 구분하기

### 5.1 편도와 왕복

거리만으로 계산한 `D/c`는 입문용 값이다. 움직이는 송신자와 수신자를 연결하려면 서로 다른 시각의 위치를 써야 한다.

- 지구에서 보이저로 송신: 지구의 송신 위치 → 이후 보이저의 수신 위치.
- 보이저에서 지구로 송신: 보이저의 송신 위치 → 이후 지구의 수신 위치.
- 즉시 응답하는 이상적인 왕복: 두 전파 시간을 합친 값, 약 이틀.
- 실제 명령·응답: 처리 시간, 운용 일정, 통신 가능 시간 등을 추가.

‘하루 기다렸다가 답신’이라는 연출은 편도 지연과 탐사선 내부 대기를 섞을 수 있다. 수신 직후 응답하는 설정이라면 응답 전의 임의 대기 24시간을 더하지 않는다.

### 5.2 특수상대론: 24시간과 139마이크로초

선택한 관성계에서 정지한 기준 시계와 속력 `v`의 시계를 비교하면:

\[
\Delta\tau=\Delta t\sqrt{1-v^2/c^2}
\]

`v=17 km/s`, `Δt=86,400초`이면:

\[
\Delta t-\Delta\tau\approx139\ \mu{\rm s}
=0.000139\ {\rm s}
\]

이는 **해당 관성계에 정지한 기준 시계와의 운동 효과만 계산한 값**이다. 실제 지구의 시계와 보이저의 시계 차이라고 제목을 붙이면 안 된다. 지구도 공전하고 있고 중력 퍼텐셜도 다르다.[S11]

영상에서는 일반 초침 두 개가 거의 함께 움직이게 한 뒤, 미세 차이 표시만 확대한다. 숫자는 실제 단위를 유지하고 `차이 표시 ×1,000,000`과 같은 배율을 명시한다.

### 5.3 일반상대론까지 고려한 교육용 근사

약한 중력장에서, 같은 좌표계에 대한 시계의 비율은 대략 다음과 같다.

\[
\frac{d\tau}{dt}\approx1+\frac{\Phi}{c^2}-\frac{v^2}{2c^2}
\]

\[
\left(\frac{d\tau_V}{dt}-\frac{d\tau_E}{dt}\right)
\approx
\frac{\Phi_V-\Phi_E-\tfrac12(v_V^2-v_E^2)}{c^2}
\]

태양만 포함한 근사에서 지구 `1 AU, 29.78 km/s`, 보이저 `173.14 AU, 17 km/s`를 대입하면:

| 기여 | 보이저 시계 − 지구 시계, 하루당 |
|---|---:|
| 운동 속도 차이 | 약 +287 μs |
| 태양 중력 퍼텐셜 차이 | 약 +848 μs |
| 합계 | 약 +1.14 ms |

이 모형에서는 보이저 쪽 시계가 더 빠르게 누적된다. 중력이 약한 곳의 시계가 상대적으로 빠르게 가는 효과가 포함되기 때문이다.[S12] 지구 자체 중력·자전·다른 천체·실제 궤도 변화·시계 오차는 제외했다.

**이 표는 가정 기반 계산이며 실제 탑재 시계 관측값, 발사 이후 누적 차이, 정밀 항법용 시간 보정값이 아니다.** 본편에서는 `139 μs`의 단순 비교 하나만 설명하고, 이 확장은 전시 해설·제작 참고로 두어도 된다.

### 5.4 상대성의 동시성: 또 다른 ‘시간 차이’

평행한 속도 `v`로 움직이는 두 관성계에서, 한 관성계가 동시에 정한 두 사건의 시간 좌표는 다른 관성계에서 대략 `|Δt'|≈vL/c²`만큼 달라질 수 있다.

`L=1광일`, `v=17 km/s`라면 약 `4.90초` 규모다. 방향에 따라 부호가 달라진다.

이 값은 24시간 전파 지연도, 하루당 시계 누적 차이도 아니다. ‘어떤 멀리 떨어진 사건들을 동시에 부를 것인가’라는 좌표계 비교다. 앞 절의 `4.90초/일`과 수치가 비슷해도 물리적 의미와 단위가 다르다. 본편에서 모두 나열하기보다 해설 자료에 남긴다.

### 5.5 도플러 효과

시선방향 후퇴 속도 `v_r≪c`의 단순 편도 예시:

\[
\frac{\Delta f}{f}\approx-\frac{v_r}{c}
\]

`v_r=17 km/s`라면 약 `−56.7 ppm`이다. 예시 반송파를 `8.4 GHz`로 두면 약 `−476 kHz`다. 이것은 특정 날짜의 실제 보이저 측정값이 아니다. 실제 통신의 송수신 주파수 계획·양방향 방식·지상국 운동 등을 반영하지 않았다.

가시광 `550 nm`에서는 약 `+0.031 nm` 규모다. 지구 전체가 붉게 바뀌는 영상은 실제 효과보다 매우 큰 과장이다. 작은 스펙트럼 이동을 보여주거나 확대 배율을 밝힌다.

### 5.6 양자역학을 넣는 이유: 전력과 빛

**A. 방사성 붕괴의 열**

보이저는 플루토늄-238의 붕괴 열을 전기로 바꾸는 RTG를 사용한다.[S09][S10]

\[
N(t)=N_0\,2^{-t/T_{1/2}}
\]

제작 모형에서 `T₁/₂=88년`을 사용한다. 개별 붕괴 시점은 확률적이지만, 매우 많은 원자가 만드는 전체 열은 비교적 안정적이다. 하루 동안 열원 세기 감소는 약 **0.00216%**다. 실제 전기 출력은 열전 변환 장치의 성능 변화 등도 반영하므로 이 식만으로 현재 전력을 확정하지 않는다.

화면의 원자 점 하나는 원자 하나를 축척대로 그린 것이 아니다. 통계적 붕괴의 표본을 상징한다. 불규칙한 개별 점멸이 부드러운 열과 전력의 흐름으로 이어지게 한다. 하루 안에 전원이 극적으로 꺼지는 서사를 물리량으로 정당화하지 않는다.

**B. 전파도 빛이며 광자 에너지를 갖는다**

\[
E=hf
\]

`h=6.62607015×10⁻³⁴ J·s`, `f=8.4 GHz`의 예시이면 광자 하나의 에너지는 약 `3.47×10⁻⁵ eV`다.[S13] 전파가 가시광보다 느리게 가는 것은 아니다. 진공에서 같은 광속으로 전파된다.

이 작품의 전파 이동·통신 설명은 고전 전자기학으로 충분하다. 양자역학은 RTG의 미시적 원리와 광자 에너지에 연결한다. 화면의 전파 입자 수를 실제 광자 수나 전송 비트 수와 일치시킬 필요는 없다. 양자 얽힘으로 24시간 지연을 없애는 설정은 사용하지 않는다.

### 5.7 관객이 혼동하지 않도록 할 최종 비교

| 항목 | 규모 또는 정의 | 성격 |
|---|---|---|
| 1광일 | 약 259억 km | 거리 |
| 편도 정보 지연 | 약 24시간 | 빛의 이동 |
| 지연의 하루 변화 | 예시 약 4.90초/일 | 상대 거리 변화 |

## 7. 장면별 연출·코딩·해설

아래 해설은 낭독용 초안이다. 장면 길이를 해설로 모두 채우지 않는다. 해설 후 3~8초 정도의 여백을 두고, 실제 녹음 길이에 맞춰 자막 큐를 조정한다.

### S01. 도착한 인사 / 00:00–00:20

**화면:** 암전 2초. 먼 빛 하나가 약하게 드러난다. 가까운 탐사선 윤곽에 작은 수신 표시가 한 번 켜진다. 지구에서 지금 막 송신하는 장면과 즉시 연결하지 않는다.

**카메라:** 보이저 주변의 외부 가상 카메라. 속도감 없이 천천히 접근.

**화면 문구:** ‘이곳에 도착한 빛은, 약 하루 전의 지구에서 출발했다.’

**코딩:** `t_receive`를 고정하고 `t_emit`를 역산한다. 수신 표시는 실제 데이터 수신 로그가 아니라 사건의 개념 표현이다.

**해설**

> 아주 멀리서 인사 하나가 도착합니다. 지구에서는 이미 다음 하루가 시작됐습니다. 이 빛이 건너온 시간만큼, 우리의 현재는 서로 어긋나 있습니다.

**소리:** 작은 전자음 한 번, 뒤이어 낮은 잔향. 우주 공간에서 직접 들리는 소리라는 설정은 쓰지 않는다.

### S02. 떠나온 경로 / 00:20–01:05

**화면:** 지구의 작은 궤도에서 출발한 선이 목성·토성 쪽으로 이어진다. 토성 이후 카메라를 기울여 평면 밖의 경로를 드러낸다. 2012년 경계 표시는 짧게 등장하고 사라진다.

**세부 배분:** 20–28초 출발 / 28–39초 목성 / 39–50초 토성 / 50–58초 2012년 / 58–65초 1광일 예측 구간.

**코딩:** 위치는 실제 벡터로 평가한다. 시간 압축은 `t_physical=f(t_video)`로 제어한다. 행성 통과에서는 속도를 늦추고 먼 항해에서는 빠르게 한다. 각 행성도 같은 물리 시각의 위치에 있어야 한다. 역사적 궤적의 다른 날짜 점들과 현재 행성 위치를 혼동하지 않게 한다.

**화면 문구:** 필요한 날짜와 행성명만. 미래 구간은 예측 표기를 사용.

**해설**

> 1977년, 보이저 1호는 지구를 떠났습니다. 목성과 토성의 중력이 길을 바꾸었고, 탐사선은 행성들이 도는 평면의 위쪽으로 향했습니다. 2012년에는 태양풍이 만드는 영역을 넘어섰습니다. 눈에 보이는 벽은 없었습니다. 지나온 경로와 측정값이 그 경계를 알려주었습니다.

**소리:** 통과 사건마다 음 하나. 충돌음·폭발음·지속 엔진음은 사용하지 않는다.

### S03. 뒤돌아본 집 / 01:05–01:35

**화면:** 1990년 실제 사진 또는 그 사진의 위치를 설명하는 도해. 촬영 날짜를 표시한다. 디졸브 뒤에는 보이저 위치에서 계산한 가상 시점이라는 표기가 나타난다. 지구는 극히 작은 점이고 태양과 가까운 방향에 놓인다.

**코딩:** 기록 이미지 레이어와 3D 렌더 레이어를 분리한다. 과거 지구 방향 벡터로 카메라를 정렬한다. 지구 위치 표시자는 원반 크기와 별도로 그린다. 지구 확대 인셋은 약 5초만 허용한다.

**화면 문구:** ‘카메라는 1990년에 꺼졌다.’ / ‘이후 장면: 위치와 빛의 이동으로 계산한 가상 시점’

**해설**

> 1990년, 보이저는 돌아보며 지구를 사진에 남겼습니다. 그 뒤 카메라는 꺼졌습니다. 지금 우리가 보는 것은 궤도와 빛의 이동으로 계산한 가상의 시선입니다. 이 거리에서 지구는 대륙도 얼굴도 구별할 수 없는, 아주 작은 빛입니다.

**소리:** 이미지가 확대될 때 소리를 키우지 않는다. 크기 확대와 실제 신호 세기는 독립적으로 처리한다.

### S04. 하루의 틈 / 01:35–02:25

**화면:** 화면 양쪽에 지구와 보이저를 둔 거리 도해. 지구에서 출발한 신호의 진행 표시가 도착점으로 향한다. 보이저의 도착 위치는 출발 당시 위치와 조금 다르다. 이어 현재 좌표의 지구와 수신되는 과거 지구를 짧게 겹쳐 보인다.

**코딩:** 수신 시각을 먼저 정하고 출발 시각을 푼다. 입자의 궤적은 그 두 사건을 잇는다. 로그로 압축한 지도에서는 실제 광속도 화면상의 일정한 픽셀 속도가 아닐 수 있다. `시간·거리 압축`을 표기한다.

**화면 문구:** ‘출발’ / ‘도착’ / ‘약 24시간’ / ‘1광일은 거리의 단위’

**해설**

> 빛은 빠르지만, 즉시 도착하지는 않습니다. 1광일은 빛이 하루 동안 가는 거리, 약 259억 킬로미터입니다. 보이저에 도착하는 지구의 모습은 그만큼 과거입니다. 그동안 지구도, 탐사선도 움직였습니다. 이곳의 응답이 다시 지구에 닿기까지도 비슷한 시간이 필요합니다.

**소리:** 송신 때 짧은 모티프를 시작하고 도착 때 다시 울린다. 영상상 간격은 압축된 지연이며 실제 24시간 대기 사운드가 아니다.

### S05. 두 장소의 하루 / 02:25–03:05

**화면:** 전체 지도에서는 거의 변화가 없다. 작은 확대창 두 개에서 지구의 변위와 보이저의 변위를 같은 눈금으로 비교한다. 시작점 잔상과 현재 위치가 조금씩 벌어진다.

**코딩:** 기준 사건 전후 12시간의 상태를 평가한다. 실제 이동거리와 지구까지의 거리 변화량은 별도 값으로 계산한다. 경로 길이는 `∫|v|dt`, 시작–끝 직선 변위는 `|r₁−r₀|`, 지구까지의 거리 변화는 `D₁−D₀`로 구별한다.

**화면 문구:** ‘같은 24시간’ / ‘확대된 변위’ / 단위와 배율.

**해설**

> 하루 동안 보이저는 약 147만 킬로미터를 이동합니다. 그래도 전체 거리 속에서는 거의 움직이지 않은 것처럼 보입니다. 지구는 태양 주위를 더 빠르게 돌고 있습니다. 두 곳 사이의 거리는 둘의 움직임을 함께 계산해야 합니다. 멀어지는 항해 안에도, 잠시 가까워지는 시간이 있습니다.

**소리:** 두 음의 느린 위상 차이. 위상 차이는 거리 변화의 예술적 매핑이라고 제작 로그에 기록한다.

### S06. 시계의 미세한 틈 / 03:05–03:35

**화면:** 같은 박자의 두 시계. 하나에는 ‘선택한 관성계의 정지 기준’, 다른 하나에는 ‘17 km/s 이동 모형’을 표시한다. 거의 같던 시계 사이의 작은 차이만 확대창에서 드러난다.

**코딩:** 기본 장면은 운동 효과만 사용한다. 전체 시계 눈금을 임의로 크게 늦추지 않는다. 확대된 차이는 원래 수치와 배율을 함께 보여준다.

**화면 문구:** ‘전파 지연 ≈ 24시간’ / ‘운동에 의한 시계 차이 ≈ 139 μs/일, 단순 모형’

**해설**

> 신호가 하루 늦는 것과 시계가 다르게 가는 것은 별개의 현상입니다. 정지한 기준 시계와 비교하면, 초속 17킬로미터로 움직이는 시계의 차이는 하루에 약 139마이크로초입니다. 실제 지구와 비교할 때는 지구의 움직임과 중력도 함께 고려해야 합니다.

**소리:** 들리는 두 박자의 큰 차이를 물리적 실제 차이처럼 표현하지 않는다. 차이를 강조할 때는 ‘시간 차이 소리화’로 처리한다.

### S07. 눈을 감은 감각 / 03:35–04:10

**화면:** 가상 카메라 화면이 어두워지고, 관측 기록의 시간축과 주파수 띠가 나타난다. 가능한 경우 2012–2013년 PWS 기록을 사용한다. 날짜가 바뀌었음을 명확히 표시한다.

**코딩:** 관측 데이터, 결측 구간, 품질 플래그를 유지한다. 파형·스펙트로그램·자기장 시각화는 독립 모듈로 둔다. 서로 다른 날짜의 자료를 ‘같은 순간’으로 합치지 않는다.

**화면 문구:** ‘플라스마파 관측 기록의 소리화 / 관측 시기: …’

**해설**

> 카메라가 꺼진 뒤에도 주변을 살피는 방법은 남아 있습니다. 자기장과 플라스마의 진동은 숫자로 기록됩니다. 지금 들리는 소리는 그 측정을 우리가 들을 수 있게 옮긴 것입니다. 여기서 감각은 풍경의 모습보다, 보이지 않는 변화의 흔적에 가깝습니다.

**소리:** 관측 자료의 주파수·진폭 관계를 보존하거나, 변환 규칙을 별도로 명시한다. 과거 음원을 2026년의 실제 소리라고 표시하지 않는다.

### S08. 원자들의 온기 / 04:10–04:40

**화면:** RTG의 개념 단면. 개별 점이 불규칙하게 변하고, 그 합이 잔잔한 열의 흐름을 만든다. 열 → 전기 → 송신의 연결을 따라가며 다시 탐사선 전체로 빠져나온다.

**코딩:** 고정된 난수 시드로 붕괴의 통계적 예시를 생성한다. 예술적 표본 수를 실제 원자 수로 해석하지 않는다. 전체 전력 밝기는 미세하게만 변하고, 빠른 깜박임은 국소적인 개념 표시로 제한한다.

**화면 문구:** ‘방사성 붕괴 → 열 → 전기’ / ‘미시적 과정의 개념 시각화’

**해설**

> 이 긴 항해를 지탱하는 전력은 원자핵의 붕괴에서 나온 열로 만들어집니다. 개별 사건의 순간은 확률적이지만, 수많은 사건이 모이면 오랫동안 이어지는 온기가 됩니다. 아주 작은 규모의 과정이, 아주 먼 곳에서 지구로 보내는 신호를 유지합니다.

**소리:** 개별 작은 소리가 지속음으로 모인다. 실제 RTG 작동음이나 전력 계측 소리라는 설정은 쓰지 않는다.

### S09. 계속 도착하는 우리 / 04:40–05:00

**화면:** 다시 가상 보이저 시점. 지구 위치 표시가 사라지고 작은 빛만 남는다. 290초 부근부터 문장, 294초부터 출처·시뮬레이션 표기. 마지막 프레임까지 아주 약한 빛을 남긴다.

**코딩:** 수신 사건의 지구 방향을 유지한다. `n=8999`가 마지막 프레임이다. 정지 이미지로 바뀌어도 배경 노이즈를 과하게 움직이지 않는다.

**화면 문구:** ‘지금 여기 도착한 것은, 어제의 우리.’ / 작품명·출처.

**해설**

> 우리에게는 이미 지나간 시간이, 저 먼 곳에는 이제 도착합니다. 같은 현재를 볼 수 없어도, 신호는 이어집니다. 지금 여기 도착한 것은, 어제의 우리입니다.

**소리:** 시작의 짧은 모티프가 돌아온다. 마지막 2초는 충분한 감쇠를 두고 끝낸다.

## 8. 데이터 취득과 재현성

### 8.1 공통 규약

| 항목 | 기본값 | 이유 |
|---|---|---|
| 위치 원점 | 태양계 질량중심, SSB | 다른 시각의 위치를 비교할 공통 기준 |
| 좌표축 | ICRF, `REF_PLANE=FRAME` | 좌표 규약을 명확하게 고정 |
| 내부 시간 | TDB, J2000 기준 경과 초 | 궤도 계산 시간 |
| 화면 시각 | UTC, 필요할 때 KST 병기 | 사람이 읽는 시각 |
| 위치 단위 | km | 광속·거리 단위 일치 |
| 속도 단위 | km/s | 광행시간·변화율 계산 |
| 원자료 보정 | `VEC_CORR=NONE` | 광행시간을 직접 계산할 때 이중 보정 방지 |
| 표 형식 | `VEC_TABLE=2` | 위치·속도 6성분 사용 |
| 화면용 좌표 | 장면별 변환 | 과학 계산용 좌표와 별도 |

Horizons의 벡터·시간·보정 옵션은 공식 규격에 따른다.[S05] NASA 웹페이지의 표시 시각을 TDB인 것처럼 그대로 입력하지 않는다. UTC→TDB 변환에는 Astropy Time 또는 적절한 SPICE 시간 커널을 사용한다.[S14]

태양 중심 좌표를 쓰고 싶다면, 같은 시각의 SSB 상태들에서 태양 상태를 빼서 지도에 표시한다. 하지만 **서로 다른 시각의 두 끝점을 연결하는 전파 계산은 SSB 상태로 수행**한다. 움직이는 태양을 각기 다른 시각에 빼고 그 결과를 그대로 거리로 삼으면 원점 이동이 섞인다.

### 8.2 자료 취득 순서

1. 대상의 식별자·사용 가능 기간·궤도 설명을 조회한다.
2. 전체 항해는 넓은 간격으로 취득한다.
3. 목성·토성 통과 구간을 별도로 고밀도 취득한다.
4. 2026년 1광일 구간은 보이저·지구·태양의 동일 기간 자료를 취득한다.
5. 광행시간 역산·왕복 계산에 필요한 앞뒤 최소 2일의 여유를 둔다.
6. 공통 시간·원점·단위·보정 상태를 검증한다.
7. 원본 응답, 요청 조건, 취득 시각, 해시를 보존한다.
8. 렌더는 저장된 자료만 읽는다. 매 프레임 인터넷 요청을 하지 않는다.

미래 위치의 예측 품질이나 궤도 경계는 응답 헤더에서 확인한다. 요청이 성공했다고 모든 구간이 관측으로 확정된 것은 아니다.

### 8.3 Horizons 취득 코드

아래는 Python 표준 라이브러리만 사용하는 취득 예제다. 본문에 실제 좌표를 포함하지 않는다. **이번 작성에서는 외부 응답까지 실행 검증하지 못했다.** 응답 형식·궤도 식별·커버리지를 확인한 뒤 사용한다.

코드의 기본 예시는 1광일 장면 주변의 짧은 기간이다. 역사 전체 자료는 `start_tdb`·`stop_tdb`·`step`을 바꿔 별도로 취득한다. 응답량이 큰 요청은 기간을 나누고 순차 처리한다.

```python
"""Run once with network access, then render from local cached files."""
import csv
import hashlib
import io
import json
import urllib.parse
import urllib.request
from datetime import datetime, timezone
from pathlib import Path

API = "https://ssd.jpl.nasa.gov/api/horizons.api"

def fetch_vectors(target, start_tdb, stop_tdb, step="1 h", out_dir="data/raw"):
    params = {
        "format": "json", "COMMAND": f"'{target}'",
        "OBJ_DATA": "'YES'", "MAKE_EPHEM": "'YES'",
        "EPHEM_TYPE": "'VECTORS'", "CENTER": "'500@0'",
        "REF_SYSTEM": "'ICRF'", "REF_PLANE": "'FRAME'",
        "OUT_UNITS": "'KM-S'", "VEC_CORR": "'NONE'",
        "VEC_TABLE": "'2'", "CSV_FORMAT": "'YES'",
        "TIME_TYPE": "'TDB'", "TIME_DIGITS": "'FRACSEC'",
        "START_TIME": f"'{start_tdb}'", "STOP_TIME": f"'{stop_tdb}'",
        "STEP_SIZE": f"'{step}'"
    }
    url = API + "?" + urllib.parse.urlencode(params)
    with urllib.request.urlopen(url, timeout=90) as response:
        raw = response.read()
    root = Path(out_dir)
    root.mkdir(parents=True, exist_ok=True)
    # Parameter hash prevents different intervals silently overwriting one another.
    key = hashlib.sha256(json.dumps(params, sort_keys=True).encode()).hexdigest()[:12]
    stem = root / f"{target}_{key}"
    stem.with_suffix(".response.json").write_bytes(raw)
    data = json.loads(raw)
    result = data.get("result", "")
    if data.get("error") or "$$SOE" not in result or "$$EOE" not in result:
        raise RuntimeError(data.get("error") or result[:1500] or "Missing vector data")
    block = result.split("$$SOE", 1)[1].split("$$EOE", 1)[0]
    parsed = []
    for row in csv.reader(io.StringIO(block)):
        if not row or not row[0].strip():
            continue
        if len(row) < 8:
            raise ValueError(f"Unexpected CSV row: {row}")
        numbers = [float(row[0])] + [float(x.replace("D", "E")) for x in row[2:8]]
        parsed.append(numbers)
    if len(parsed) < 2 or any(b[0] <= a[0] for a, b in zip(parsed, parsed[1:])):
        raise ValueError("Missing or non-monotonic epochs")
    csv_path = stem.with_suffix(".csv")
    with csv_path.open("w", encoding="utf-8", newline="") as f:
        writer = csv.writer(f)
        writer.writerow(["jd_tdb", "x_km", "y_km", "z_km",
                         "vx_km_s", "vy_km_s", "vz_km_s"])
        writer.writerows(parsed)
    meta = {
        "fetched_at_utc": datetime.now(timezone.utc).isoformat(),
        "parameters": params,
        "source_url": url,
        "raw_sha256": hashlib.sha256(raw).hexdigest(),
        "response_header": result.split("$$SOE", 1)[0],
        "rows": len(parsed),
        "note": "Read the returned trajectory header before assigning observed/predicted status."
    }
    stem.with_suffix(".meta.json").write_text(
        json.dumps(meta, ensure_ascii=False, indent=2), encoding="utf-8")
    return csv_path

if __name__ == "__main__":
    # Sequential requests. Dates in this example are TDB calendar dates.
    for body in (-31, 399, 10):
        print(fetch_vectors(body, "2026-11-16", "2026-11-21"))
```

## 9. 핵심 물리 계산 코드

다음 코드는 NumPy를 사용한다. 실제 궤도 CSV를 입력하면 보간, 상대 거리, 광행시간, 1광일 거리 교차, 시계 근사를 계산할 수 있다.

- 광행시간은 평탄한 시공간에서 빛의 이동으로 계산한다.
- 항성광행차, 중력에 의한 빛의 굴절, Shapiro 지연, 대기·플라스마 통과 지연은 포함하지 않는다.
- 카메라의 정밀한 겉보기 방향이 필요하면 적절한 SPICE 커널과 `CN+S` 같은 수신 시점 보정을 검토한다. 송신 방향은 수신 방향 보정과 구분한다.[S15]
- SPICE가 보정한 벡터에 아래 광행시간 보정을 다시 적용하지 않는다.
- 코드의 수렴 허용오차는 수치 연산의 기준이며 실제 궤도 오차가 아니다.

```python
"""LightDayGap calculation reference. Inputs: km, km/s, TDB seconds."""
import csv
from pathlib import Path
import numpy as np

C = 299792.458
DAY = 86400.0
AU = 149597870.7
JD0 = 2451545.0

class Ephemeris:
    """Cubic Hermite states. No extrapolation beyond supplied data."""
    def __init__(self, t, positions, velocities):
        self.t = np.asarray(t, dtype=np.float64)
        self.p = np.asarray(positions, dtype=np.float64)
        self.v = np.asarray(velocities, dtype=np.float64)
        if self.t.ndim != 1 or len(self.t) < 2:
            raise ValueError("At least two epochs are required")
        if self.p.shape != (len(self.t), 3) or self.v.shape != self.p.shape:
            raise ValueError("Expected N by 3 state arrays")
        if not all(np.isfinite(a).all() for a in (self.t, self.p, self.v)):
            raise ValueError("Non-finite state")
        if np.any(np.diff(self.t) <= 0):
            raise ValueError("Epochs must increase strictly")

    @classmethod
    def from_csv(cls, path):
        with Path(path).open(encoding="utf-8", newline="") as f:
            rows = list(csv.DictReader(f))
        t = [(float(r["jd_tdb"]) - JD0) * DAY for r in rows]
        p = [[float(r[k]) for k in ("x_km", "y_km", "z_km")] for r in rows]
        v = [[float(r[k]) for k in ("vx_km_s", "vy_km_s", "vz_km_s")] for r in rows]
        return cls(t, p, v)

    def state(self, t):
        t = float(t)
        if not self.t[0] <= t <= self.t[-1]:
            raise ValueError("Epoch outside coverage; fetch a wider interval")
        i = min(np.searchsorted(self.t, t, side="right") - 1, len(self.t) - 2)
        h = self.t[i + 1] - self.t[i]
        u = (t - self.t[i]) / h
        p0, p1, v0, v1 = self.p[i], self.p[i+1], self.v[i], self.v[i+1]
        p = ((2*u**3-3*u**2+1)*p0 + (u**3-2*u**2+u)*h*v0
             + (-2*u**3+3*u**2)*p1 + (u**3-u**2)*h*v1)
        v = ((6*u**2-6*u)*p0/h + (3*u**2-4*u+1)*v0
             + (-6*u**2+6*u)*p1/h + (3*u**2-2*u)*v1)
        return p, v

def geometric(t, earth, voyager):
    pe, ve = earth.state(t)
    pv, vv = voyager.state(t)
    d = pv - pe
    distance = float(np.linalg.norm(d))
    if distance == 0:
        raise ValueError("Coincident endpoints")
    radial_speed = float(np.dot(d / distance, vv - ve))
    return {"distance_km": distance, "range_rate_km_s": radial_speed,
            "geometric_light_time_s": distance / C}

def reception(t_receive, emitter, observer, tolerance_s=1e-7):
    """Past emission event whose light reaches observer at t_receive.
    Flat-space propagation only; no stellar aberration or Shapiro delay.
    """
    po, _ = observer.state(t_receive)
    delay = float(np.linalg.norm(emitter.state(t_receive)[0] - po) / C)
    for _ in range(40):
        pe, _ = emitter.state(t_receive - delay)
        new_delay = float(np.linalg.norm(pe - po) / C)
        if abs(new_delay - delay) < tolerance_s:
            pe, _ = emitter.state(t_receive - new_delay)
            return {"emission_tdb_s": t_receive - new_delay,
                    "delay_s": new_delay, "vector_to_emitter_km": pe - po}
        delay = new_delay
    raise RuntimeError("Light-time solve did not converge")

def transmission(t_emit, emitter, receiver, tolerance_s=1e-7):
    """Future receive event for a pulse sent at t_emit."""
    pe, _ = emitter.state(t_emit)
    delay = float(np.linalg.norm(receiver.state(t_emit)[0] - pe) / C)
    for _ in range(40):
        pr, _ = receiver.state(t_emit + delay)
        new_delay = float(np.linalg.norm(pr - pe) / C)
        if abs(new_delay - delay) < tolerance_s:
            return {"receive_tdb_s": t_emit + new_delay, "delay_s": new_delay}
        delay = new_delay
    raise RuntimeError("Light-time solve did not converge")

def first_light_day_crossing(earth, voyager, start, stop, step_s=DAY):
    """First sampled below-to-above crossing, then bisection.
    Search a broad interval; step_s must resolve any repeated crossings.
    """
    def residual(t):
        return geometric(t, earth, voyager)["distance_km"] - C * DAY
    a, fa = float(start), residual(start)
    if fa >= 0:
        raise ValueError("Search start must precede the first crossing")
    while a < stop:
        b = min(a + step_s, stop)
        fb = residual(b)
        if fa < 0 <= fb:
            lo, hi = a, b
            while hi - lo > 0.01:
                mid = (lo + hi) / 2
                if residual(mid) < 0:
                    lo = mid
                else:
                    hi = mid
            return (lo + hi) / 2
        a, fa = b, fb
    raise ValueError("No crossing in supplied interval")

def sr_coordinate_lag(dt_s, speed_km_s):
    """Lag vs a clock at rest in the selected inertial frame."""
    beta2 = (speed_km_s / C)**2
    if not 0 <= beta2 < 1:
        raise ValueError("Timelike speed required")
    # Stable form of dt * (1 - sqrt(1 - beta^2)).
    return dt_s * beta2 / (1 + np.sqrt(1 - beta2))

def weak_field_rate_difference(v_e, v_v, r_e, r_v, gm_sun):
    """Approximate (Voyager rate - Earth rate), Sun-only model."""
    phi_e, phi_v = -gm_sun / r_e, -gm_sun / r_v
    return (phi_v - phi_e - (v_v*v_v - v_e*v_e)/2) / (C*C)
```

### 9.1 가장 중요한 호출 방향

`reception(t_receive, emitter, observer)`에서 **emitter는 과거에 빛을 낸 대상**, **observer는 지금 받는 대상**이다.

```python
# earth와 voyager는 같은 SSB/ICRF/TDB 규약의 Ephemeris 객체.
earth_seen_from_voyager = reception(t_receive, earth, voyager)
voyager_seen_from_earth = reception(t_receive, voyager, earth)

# 지구에서 송신한 한 신호가 언제 보이저에 도착하는가.
outbound = transmission(t_emit, earth, voyager)

# 이상적으로 즉시 응답하는 경우, 다시 지구에 도착하는 시각.
inbound = transmission(outbound["receive_tdb_s"], voyager, earth)
round_trip_s = inbound["receive_tdb_s"] - t_emit
```

위 두 `reception` 호출의 지연이 언제나 같다고 가정하지 않는다. 같은 ‘지금’에 수신한 두 신호는 서로 다른 과거의 출발 사건을 연결한다.

### 9.2 1광일 교차 시점 계산

위 `first_light_day_crossing`은 **같은 시각의 기하학적 거리**가 1광일을 처음 아래에서 위로 넘는 지점을 찾는다.

- 예를 들어 2026년 전체를 넓게 조사한 다음 교차 구간을 좁힌다.
- 관측 범위 밖이나 예측 범위 밖으로 외삽하지 않는다.
- 1시간 자료와 더 촘촘한 자료의 결과를 비교해 보간에 따른 차이를 확인한다.
- 연중 지구 공전 효과가 있으므로 전체 거리가 항상 단조 증가한다고 가정하지 않는다.
- 더 작은 간격으로 조사했을 때 추가 교차가 없는지 확인한다.
- NASA 공표 시각과 차이가 나면 거리 정의·시간척도·좌표 중심·궤도 자료의 버전부터 확인한다.
- **기하학적 거리 1광일과 특정 방향의 실제 전파 시간 정확히 24시간은 별도의 사건 정의다.**

### 10.4 영상 시간과 물리 시간

- `t_video = frame_index / fps`.
- 장면 선택은 `start ≤ t_video < end`.
- 역사 장면은 사건 사이의 구간별 시간 매핑을 사용한다.
- 하루 장면은 `t_world = t_start + u × 86,400`.
- 관측 기록 장면은 기록 자체의 시각을 사용한다.
- 프레임마다 시스템의 현재 시각을 읽지 않는다.
- 코딩 시점의 ‘오늘’을 계속 참조하면 나중에 같은 영상을 재생성할 수 없으므로 기준 사건을 설정 파일에 고정한다.

```python
# 렌더러가 갖춰야 할 인터페이스를 설명하는 의사코드.
# load_scene_state, draw_scene, write_frame은 구현해야 한다.
for frame_index in range(9000):
    t_video = frame_index / 30.0
    state = load_scene_state(t_video, cached_data, film_config)
    rgba = draw_scene(state, film_config)
    write_frame(frame_index, rgba)
```

### 10.5 좌표를 화면으로 옮기는 규칙

1. 계산은 `float64`로 유지한다.
2. 카메라 또는 장면 원점을 먼저 뺀다.
3. 적절한 길이 단위로 나눈다.
4. 그 뒤 GPU용 `float32`로 바꾼다.
5. 깊이 범위가 크게 다른 기체·행성·궤적·항성을 레이어나 패스로 분리한다.

수백억 km의 좌표와 몇 m짜리 탐사선을 하나의 단정밀도 공간에 그대로 넣으면 떨림·깊이 오류가 생길 수 있다. 떠 있는 원점과 장면별 축척을 사용한다.

ICRF에서 황도면 지도 좌표로 변환할 때는 고정 회전 행렬을 적용한다. 이름만 ‘황도면’이라고 쓰고 ICRF의 z축을 그대로 황도 북극으로 취급하지 않는다. 렌더러의 위쪽 축을 바꾸는 변환도 위치·속도·카메라에 일관되게 적용한다.

전체 궤도 지도에는 다음 같은 거리 압축을 사용할 수 있다.

\[
\mathbf r_{\rm display}
=\frac{\mathbf r}{|\mathbf r|}
\,L_0\log\left(1+\frac{|\mathbf r|}{L_0}\right)
\]

`r=0`은 별도로 처리한다. 이 변환은 지도용이다. 보이저 가상 관측 시점의 실제 각도와 지구 크기 계산에는 적용하지 않는다.

### 10.6 가상 관측 카메라

- 카메라 원점: `r_V(t_receive)`.
- 목표 방향: `r_E(t_emit) − r_V(t_receive)`.
- 태양도 필요하면 별도의 방출 시각을 계산한다.
- 프레임의 위쪽 방향은 안정된 기준축에서 정하고, 시선과 거의 평행할 때 다른 축으로 전환한다.
- 지구의 과거 좌표를 사용하면서 지구 표면만 현재 시각으로 돌리지 않는다.
- 지구의 위상을 보여줄 때는 지구–태양–보이저 기하를 사용한다.
- 정밀한 반사광 모형에서는 태양→지구 이동 시간까지 고려한다. 본편에서는 이 부분을 근사해도 되지만 범위를 기록한다.
- 성간 공간의 시각적 정적을 유지한다. 변화가 거의 없다는 것이 계산 실패의 증거는 아니다.

### 10.7 보여주는 크기와 물리적 크기

각 객체에는 세 값을 따로 둔다.

- `physical_radius_km`: 계산용 실제 반지름.
- `render_radius`: 지도에서 보이도록 키운 크기.
- `marker_radius_px`: 위치를 알려주는 기호 크기.

지구의 지도용 구체 크기를 키운 뒤 그 크기로 시직경이나 위상을 계산하지 않는다. 점광원의 번짐은 표시·노출 효과로 별도 관리한다.

## 11. ‘보이저의 감각’을 만드는 계측·음향

### 11.1 장치 상태의 기준일

작성일에 확인한 NASA 상태표에는 MAG와 PWS가 작동 중으로, CRS와 LECP는 각각 2025년 2월과 2026년 4월 전력 절약을 위해 꺼진 것으로 안내되어 있다.[S01]

이를 2026년 11월의 확정된 장치 상태로 외삽하지 않는다. 본편의 S07은 날짜가 확인되는 기록 자료를 사용하고, 전시 시점의 상태는 공식 페이지를 다시 확인한다.

### 11.2 데이터 매핑

| 입력 | 화면 | 소리 | 주의점 |
|---|---|---|---|
| 자기장 크기, nT | 선의 밝기·두께 | 낮은 음의 음색 | 실제 자기장 선이 눈에 보인다는 뜻 아님 |
| 자기장 방향 | 방향성 선 구조 | 좌우 공간 배치 | 같은 좌표계인지 확인 |
| PWS 스펙트럼 | 시간–주파수 띠 | 대응 주파수의 음 | 기록 시각·빈 구간 유지 |
| 전파 지연 | 두 사건 사이 간격 | 모티프의 재등장 | 영화 시간으로 압축됨 |
| 수신 세기의 모형 | 밝기·노이즈 비율 | 신호와 배경의 비율 | 실제 SNR로 주장하려면 링크 예산 필요 |
| RTG 모형 | 완만한 열 흐름 | 연속음 | 실제 전력 텔레메트리와 구분 |

아이오와대학교는 보이저 PWS 기록의 스펙트로그램과 가청화 예시를 제공한다. 해당 예시는 2012–2013년의 현상을 보여주며, 시간 압축과 주파수의 관계를 설명한다.[S08]

실제 데이터를 확보하지 못했다면:

- 합성 파형에 ‘관측 기반’이라는 이름을 붙이지 않는다.
- `플라스마파를 설명하는 합성 음향`이라고 표시한다.
- 기록 결측을 임의 파형으로 메우지 않는다.
- 서로 다른 기간의 데이터를 한 장면에 쓸 경우 각 기간을 표기한다.

### 11.3 시간 압축과 음높이는 별개다

관측 24시간을 영상 40초에 넣으면서 녹음 자체를 2,160배 빠르게 재생하면 음높이도 바뀐다. 시간 변화의 포락선을 압축하고, 가청 주파수는 별도의 규칙으로 합성하는 방법을 사용할 수 있다.

규칙 예:

\[
f_{\rm audio}(t)
=f_{\min}+(f_{\max}-f_{\min})\,g(x(t_{\rm data}))
\]

`g`의 범위·정규화·클리핑 규칙을 기록한다. 로그 스케일을 썼다면 선형 비례인 것처럼 설명하지 않는다. 센서 채널이 실제로 가청 주파수 범위인 경우에도 전기적 측정을 스피커 소리로 변환했다는 점은 유지한다.

### 11.4 오디오 제작 규격

- 길이: 300초.
- 샘플레이트: 48,000 Hz.
- 총 샘플 프레임: 14,400,000개, 스테레오면 채널당 같은 길이.
- 30fps에서 영상 한 프레임은 오디오 1,600샘플에 대응.
- 해설, 음악, 데이터 음향을 별도 트랙으로 만들고 마지막에 합친다.
- 해설이 있는 구간에는 배경을 낮춘다. 소리화 데이터의 ‘보존용 원본’은 별도로 유지한다.
- 약한 신호를 다루더라도 시끄러운 화이트노이즈가 영상 전체를 덮지 않게 한다.
- 전송 에러율이나 실제 수신 SNR은 자료 없이는 숫자로 단정하지 않는다.

## 12. 재현 가능한 렌더와 영상 출력

### 12.1 프레임 생성

- `render(frame_index)`가 같은 입력에서 같은 결과를 만들도록 한다.
- 난수는 시드를 고정한다. 임의 프레임부터 렌더할 수 있게 이벤트 시퀀스를 미리 생성하거나 시간으로 직접 평가한다.
- 파티클 위치를 ‘이전 프레임 위치 + delta’로만 누적하지 않는다. 프레임을 건너뛰어도 같은 시각을 재현해야 한다.
- 모션블러가 필요하면 한 프레임 안의 여러 물리 시각을 평가한다.
- 오프라인 출력 시간과 작품 시간은 독립적이다. 렌더가 느려도 최종 영상은 정확히 30fps다.
- 파일명 예: `frame_00000.png`부터 `frame_08999.png`.

### 12.2 출력 명령 예시

프레임과 오디오가 준비되었다는 전제의 FFmpeg 예시다.[S17]

```bash
ffmpeg -framerate 30 -start_number 0 \
  -i output/frames/frame_%05d.png \
  -i output/audio/mix.wav \
  -map 0:v:0 -map 1:a:0 \
  -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p \
  -r 30 -t 300 \
  -c:a aac -b:a 320k -ar 48000 \
  -movflags +faststart \
  output/Voyager1_LightDayGap_5min.mp4
```

색공간·전송함수·범위는 렌더부터 인코딩까지 일관되게 설정한다. 이미지를 어떤 색공간으로 출력했는지 확인하지 않고 메타데이터만 Rec.709라고 붙이지 않는다. 어두운 그라데이션의 밴딩이 크면 10비트 마스터를 별도로 만들고 배포용 파일을 변환한다.

### 12.3 최종 제작 산출물

| 산출물 | 내용 |
|---|---|
| `Voyager1_LightDayGap_5min.mp4` | 해설 포함 최종 영상 |
| `Voyager1_LightDayGap_no_narration.mp4` | 선택 사항, 전시용 무해설 버전 |

## 13. 구현 순서와 완료 기준

### 단계 A. 과학 데이터

1. 저장소를 읽고 실행 방법·기존 스택·관련 지침을 확인한다.
2. 실제 벡터를 취득하고 출처·범위를 고정한다.
3. 목성·토성 경로와 현재 방향을 검증한다.
4. 지구–보이저 거리와 두 방향의 광행시간을 계산한다.
5. 공표된 1광일 시각과 계산 정의를 비교한다.

**완료 기준:** 장면에 들어갈 수치에 출처·가정·시간척도가 있다. 임의 좌표가 실제 궤적으로 섞이지 않는다.

### 단계 B. 1080p 움직임 시안

1. 9개 장면을 단순 도형으로 구현한다.
2. 날짜와 시점의 전환을 확인한다.
3. 24시간 변화량 확대창과 시계 비교를 완성한다.
4. 300초 전체 무음 시안을 만든다.

**완료 기준:** 장면 사이의 시간·시점 혼동이 없고, 데이터 누락을 숨기지 않는다.

### 단계 C. 해설·관측 소리화

1. 제7절의 해설을 녹음하고 길이를 확인한다.
2. 실제 관측 자료 또는 명시적인 합성 대체를 선택한다.
3. 자막을 오디오에 맞춰 배치한다.
4. 침묵과 잔향을 포함해 300초에 맞춘다.

**완료 기준:** 해설을 이해할 수 있고, 데이터 음향을 실제 우주 녹음으로 오해하게 하지 않는다.

### 단계 D. 4K 최종 출력

1. 실제 사용할 기체 모델·이미지·폰트의 출처와 이용 조건을 기록한다.
2. 장면 표기·과장 배율·예측 구간 표기를 확인한다.
3. 9,000프레임과 300초 오디오를 인코딩한다.
4. 전체 재생과 시작·끝·장면 경계 프레임을 확인한다.

**완료 기준:** 영상 길이·프레임 수·자막·음향이 일치하고 같은 설정으로 재현된다.

> 실제 궤도는 JPL Horizons 또는 적절한 SPICE 자료를 취득해 사용한다. SSB·ICRF·TDB·km·km/s 규약을 통일하고, 원자료와 출처를 보존한다. 자료가 없으면 ‘개념 시안’으로만 출력한다.
>
> 보이저가 보는 지구는 수신 시각에서 방출 시각을 역산한 가상 시점으로 구현한다. 1990년 이후 실제 카메라 영상이라고 표시하지 않는다. 지구 원반, 위치 표시자, 확대 인셋을 분리한다.
>
> 지구–보이저 거리, 태양–보이저 거리, 기하학적 광행시간, 송수신 광행시간, 시선방향 속도를 별도 값으로 관리한다. 실제 지구 시계 비교와 17 km/s 정지 기준 비교도 구분한다.
>
> 제6·7절의 9개 장면과 해설을 구현한다. 미래 구간, 과거 관측 자료, 수치 확대, 합성 음향을 명확히 표시한다. 양자역학은 RTG 붕괴와 광자 에너지에 연결한다.
>
> 난수 시드·기준 시각·프레임 시각을 고정하고, 1080p 시안 뒤 4K 9,000프레임을 만든다. 오디오는 48kHz·300초로 맞춘다. 제14절 검증 결과와 실제 실행한 범위를 기록하고, 원자료·코드 리비전·설정으로 결과를 재현할 수 있게 한다.
